# Tique v0.7.0-alpha.1 — categories and tags

**Issue confirmed on-device:** nine classification failures were reported in this version. The duplicate-name lookup prevented creating options because null arguments were passed to SQLCipher. Use the [0.7.1 fix](https://github.com/richardheise/Tique/releases/tag/v0.7.1-alpha.1), installing over the existing app. Historical 0.7.0 attachments and tag remain intact.

Each notification review may have a main category, such as Food, Leisure, or Bills, and several context tags, such as Travel and Work. These options are independent of financial nature (income, expense, transfer, or other).

In **Interpret original**, choose a category and tags and tap **Save review**. **Manage categories and tags** lets you create, rename, archive, and reactivate options. It is also available in Advanced settings, without opening a notification. Renaming keeps links. Archiving preserves existing selections and prevents new ones; reactivating makes the option available again. Up to 200 options and 20 tags per review. Duplicate names of the same type are rejected, including archived ones.

The encrypted catalog is permanent in this installation and survives deletion of temporary records. Old reviews with free-text categories are preserved; choosing a catalog category links it by ID.

## Limits

This is still diagnostics: it does not confirm transactions, change balance, or total real spending by category. Observations and their reviews, including selections, expire after seven days; the catalog remains. **The catalog is not yet included in local copies or synthetic portable backup; uninstall removes it.** The management screen also states this. There is no automatic classification, validated Nubank template, silent rule creation, or new dependency.

Package, certificate, keys, and previous formats were retained. Install over the existing app; do not uninstall. APK arm64-v8a/Android 8+, version 0.7.0/code 8, offline bundle, and no INTERNET. AGPL-3.0-only source and notices accompany the distribution.

## Test on the phone

1. Install over 0.6.1. Check that observations still within retention and earlier reviews remain.
2. In Advanced settings, run **Run isolated native checks**. Expected: **60 passed, zero failures, and zero not verified**. The battery pauses capture; start another consented session afterward. Old-version counters do not replace this battery.
3. On an observation, tap **Interpret original**. Keep the real value, choose nature, category **Food**, and create two fictitious tags, for example **Travel** and **Test**. Select both and tap **Save review**.
4. Close and reopen the preview, tap **Reprocess**, exit and reopen the app: category, tags, and other saved corrections should remain, without duplicating the preview.
5. In management, rename a used option. When reopening the review, the new name should appear and remain selected. Archive it: the existing review keeps its selection, but another observation does not offer the option. Reactivate it and check that it is offered again. Removing a tag from a review must not delete it from the catalog.
6. Try creating a duplicate name and an empty name: both should be rejected without changing existing data. Also check an old review with a free-text category: the old text should remain until a new option is chosen.
7. Optional, destructive only to diagnostics: after checking all other steps, **Delete temporary records** should delete observations and their reviews while preserving categories and tags in management. There is no need to do this to records you want to keep.

Report counters, codes, and results only. Do not send original notifications, personal values, or passwords in this conversation. Additional scenarios and consequences are in [ADR 0010](https://github.com/richardheise/Tique/blob/v0.7.0-alpha.1/docs/adr/0010-categorias-e-tags-do-diagnostico.md).
