# FFortuna v0.6.0-alpha.1 — BRL preview of the original

Experimental Android prerelease: internal version 0.6.0 (versionCode 6), package `org.ffortuna.capturepoc`, arm64-v8a, Android 8/API 26+. Adds preliminary value interpretation in encrypted diagnostics, without a real financial ledger or automatic postings.

## What changed

- Generic parser `notification-brl/1`: recognizes R$/BRL markers, comma with two decimal digits, and period-separated thousands. Uses safe integer cents and preserves exact snippet, field, and UTF-16 position as evidence.
- No reviewed sample is available in the development environment to support Nubank-specific rules. No bank templates were invented; Nubank parsing is not validated.
- Ambiguous/incomplete/negative values, zero, truncated values, values without a marker, or values outside limits remain unselected. Nature, account, and effective date are not guessed. A lone price does not prove a movement.
- “Interpret original” provides local review of amount, nature, optional date, description, and category. Reprocessing keeps saved corrections without creating another preview for the same observation. Observations with their own identities remain separate.
- Updates show the Android identity relationship without concluding they are the same transaction. Group summaries do not create candidates.
- Transactional 1→2 migration preserves originals/key/export revisions and pauses old consent. A newly consented session interprets new observations after durable write in Kotlin, without depending on JavaScript. Old items require explicit action.
- “Prepare copy for export” now explains that R$ 12,34 is fictitious only in that copy. The parser uses the original with real values; its previews/corrections are not exported.

**Previews and corrections are temporary diagnostic data and expire with the observation after 7 days. They do not change balance, confirm transactions, or enter synthetic backups.**

## Install and test

Install over 0.5.0 without uninstalling: package and signature are unchanged. Download `ffortuna-capture-poc-arm64.apk` from the attachments.

1. In Advanced settings, run the **48 isolated native checks**. Real collection requires these checks to pass in the current process and new consent.
2. On an existing individual observation, tap **Interpret original**. Check the real value and evidence; an ambiguous format should leave the value empty for review.
3. Correct fields and **Save review**. Tap **Reprocess** and reopen the app: the correction must remain and no second candidate should appear for the same observation.
4. To validate background operation, start a new session and wait for a legitimate notification during normal use. Check interpretation time on return; a bank operation is not required for testing.

[Full procedure](https://github.com/richardheise/Tique/blob/v0.6.0-alpha.1/docs/previa-brl.md). Report only counters/codes/results, without originals, passwords, or financial content in this conversation.
