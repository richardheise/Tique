# Tique v0.7.1-alpha.1 — fix for creating categories and tags

Fixes the duplicate-name lookup that prevented creating categories and tags and caused nine failures in the 0.7.0 classification battery, as reported on-device. The code passed null values to the text arguments of `rawQuery`; SQLCipher 4.19.1 rejects them in `bindString` before running SQL. The `? IS NULL` condition did not avoid the error.

The query now includes ID exclusion only when renaming; creation receives only type and name in an `Array<String>` without null parameters. Duplicate names remain blocked, including archived options. Files, keys, IDs, schemas, and links do not change. No migration or data cleanup; **install over the existing app, do not uninstall**. APK 0.7.1/versionCode 9, same Android package and signature.

## Test on the phone

1. Install `tique-arm64.apk` from the attachments over the previous version.
2. In Advanced settings, rerun native checks. Expected: **60 passed, zero failures, and zero not verified**. Capture is paused during the battery; start another consented session afterward.
3. In **Manage categories and tags**, create a fictitious category and tag, rename, archive, and reactivate them. Try repeating a name and check that it is rejected.
4. In **Interpret original**, select a category and tag, save, and reopen. Reprocess and restart the app: selection should remain. Do not send notification data, only results and any error codes.

Other limits from [0.7.0](https://github.com/richardheise/Tique/blob/v0.7.0-alpha.1/docs/releases/v0.7.0-alpha.1.md) remain: reviews are temporary for seven days, encrypted catalog remains permanent in this installation without backup, and there are no real financial reports or automatic classification.
