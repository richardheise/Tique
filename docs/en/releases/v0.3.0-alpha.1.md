# FFortuna v0.3.0-alpha.1 — synthetic capture and backup

Experimental Android prerelease, using fictional data only. The APK uses internal version 0.3.0 (versionCode 3), package `org.ffortuna.capturepoc`, arm64-v8a, and Android 8/API 26 or later. It does not capture Nubank or accept real financial data/statements.

The proof includes Kotlin capture independent of the interface, SQLCipher/Keystore vault, identities/revisions, reprocessing, and diagnostics. This version adds password-protected portable backup without raw payloads, with restoration to a new vault while preserving the previous one. The financial demo remains separate in Expo Go.

## Install and validate

Download `ffortuna-capture-poc-arm64.apk` from the prerelease attachments. Transfer it to the phone and open the file. The signing certificate is the same as previous versions; it can be installed over them. If you have already uninstalled, old local data/key will not be available without a previous backup.

In the app, prepare the authorizations in section 1 and publish fixtures in section 2. In section 4, save a backup to a local folder, test an incorrect password, and restore with the correct password. To test recovery without the old key, first verify the file outside the app and keep the password; then uninstall, reinstall, and restore. Full procedure: [captura-nativa.md](https://github.com/richardheise/Tique/blob/v0.3.0-alpha.1/docs/captura-nativa.md#backup-portátil--roteiro-030).

## Validation and limits

- Strict TypeScript, 30 demo tests, and 13 native JVM tests passed.
- Thirteen instrumented tests compiled but were not run. They also cover Keystore, auxiliary files, backup, and interrupted staging.
- APK inspected: signature, no INTERNET, Android automatic backup disabled, offline JavaScript, license notices, and 23 native libraries aligned to 16 KB.
- The user approved the 0.2.1 manual capture procedure on Samsung Galaxy A36 SM-A366E/DS, Android 16. **On 25/10/2026, the user also approved all eight steps of the 0.3.0 manual backup/restore procedure on that device, including wrong password, vault switching, reinstall without the old key, and persistence/integrity.**
- Backup does not include the Expo Go financial database or raw payloads. Observations without raw data are explicitly not reprocessable. Another restoration requires discarding any preserved previous vault first.
- Inactive-vault retention, instrumented test execution, and file/log review need validation before diagnostics with real notifications. No lossless-capture or Nubank-support claim is made.

## Repeat the build

With the local toolchain described in the procedure, Node 24, and dependencies installed:

```sh
nvm use
npm ci
npm run check
npm run native:build -- --compile-device-tests
```

The build keeps a hard limit of 12 GiB and up to 16 CPUs via systemd/cgroup. EAS, an Expo account, or a paid service is not required. Downloads are for development; the final APK works without Metro and without INTERNET.
