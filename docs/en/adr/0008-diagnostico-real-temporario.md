# Temporary diagnostics for real notifications

User-authorized decision on 26/10/2026 (“go ahead”). This is a local, temporary notification-review tool for package `com.nu.production`, listed on [Google Play](https://play.google.com/store/apps/details?id=com.nu.production). Package presence and the installed signature are checked on-device. The observed signature is trust on first use (TOFU); it does not prove the publisher is official. A source change or unavailability pauses the session.

Starting a session requires the 40 synthetic checks for this version to pass in the current process; failures and unverified items block startup. The result is not persisted as permanent authorization. A consented session may continue when only the process is recreated in the same boot, within the original term.

Each session requires explicit consent and lasts at most 24 hours of monotonic-clock time, until device reboot or a clock change to before the start, and at most 200 observations in total retained. At most 20 revisions are kept. Records expire after seven days when the core runs. Only notifications published after session start are included. Source, signature, and consent are checked before accessing text; package filters and group summaries are applied before reading extras. Group summaries retain metadata only.

Collection stores only title, text, expanded text, subtext, and text lines, with a total limit of 16,000 characters, up to 4,096 characters per field, and at most 32 lines. Identity and revisions are separated by source key and fingerprint; updates create a revision without confusing distinct notifications. There is no parser, posting, balance, or change to the synthetic vault. Data is held in a separate SQLCipher database with its own Android Keystore key and the module's existing encryption policies. Synthetic schemas are preserved; there are no new dependencies, INTERNET permission, or remote upload. Diagnostics are not included in synthetic backups.

The suggested data-removal mask covers known patterns but does not guarantee anonymization. Names, merchants, places, accounts, and free text require manual review before confirmation. Export is optional, contains only reviewed and confirmed fields, and uses a password-encrypted file via `BackupCodec` (PBKDF2 and AES-GCM, as in ADR 0006). The format excludes real identifiers, times, signatures, grouping keys, and originals. Checking a file only decrypts and validates it in memory; it never imports records.

The release APK uses `FLAG_SECURE`; when leaving the app or going to the background, the interface clears originals, editable fields, and passwords it controls. This does not compensate for keyboards, autofill, internal string copies, or process memory; complete erasure of this data is not promised. The document picker is provided by Storage Access Framework; the user chooses the encrypted file destination.

Alternatives considered: collecting no real notifications would reduce risk but would not allow reviewing received content; capturing all notifications would collect unnecessarily; a parser or integration with postings would mix diagnostics with financial processing; exporting originals or including diagnostics in synthetic backup would expose more data. These were rejected. The consequence is that retained data remains sensitive despite separation and encryption; consent, limits, mandatory review, and local disposal reduce but do not eliminate risk. Android may hide or alter fields, and complete capture is not guaranteed.

The user reported approving 30 interface checks for version 0.4.0 on 26/10/2026, with no failures or unverified items. This report is not a JUnit runner execution and does not validate real diagnostics or bank-notification capture.
